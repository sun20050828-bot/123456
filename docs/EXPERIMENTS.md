# 实验协议与有效性边界

## 研究问题与可检验假设

**RQ1：增加 worker 是否线性提高吞吐？**

H1：有模拟 handler 耗时的固定积压，在低并发时可通过重叠 handler 增加吞吐，
但 SQLite 的串行写入会限制扩展性。结果可能推翻“增加 worker 必然更快”的假设。

**RQ2：同步策略是否改变吞吐与尾延迟？**

H2：FULL/NORMAL 可能具有不同 I/O 成本；单机结果需要结合日志模式、缓存和磁盘解释。
本实验不测量断电耐久性，不能用吞吐实验验证掉电数据安全。

**RQ3：租约能否保证外部副作用恰好一次？**

H3：只采用租约时不能；业务事务唯一 key 可消除本实验的重复 receipt。

## 性能 workload

预先插入 N 个任务，每个 payload 仅有序号。每个消费者独立进程、独立连接，
均报告就绪后由 Event 同步启动。领取、模拟 I/O 等待、ack，直到当前队列无可领取任务。
进程启动采用 spawn，Windows/Linux 使用同一逻辑。

- 默认矩阵：worker ∈ {1,2,4}；synchronous ∈ {FULL,NORMAL}；journal=DELETE。
- 本次实测 N=160、模拟 handler=2ms、每组 3 次，总共 18 个 trial。
- 顺序由固定随机种子 20261004 打乱，减少固定顺序的系统性偏差。
- 模拟的是 sleep 型 I/O 等待，不代表 CPU 密集应用。
- 每 trial 使用新的临时数据库；不声称冷缓存，OS page cache 不主动清理。
- 可使用已修复 SQLite 运行 `--journal WAL` 进行日志模式消融。

吞吐时间范围：父进程发出 Event 前的 perf_counter 到最慢 worker 最后一次空轮询结束。
不包括插入、进程启动、连接关闭、结果收集和统计验证。包含调度唤醒开销。
claim 延迟包括获得数据库 writer lock 和提交，记录仅成功领取；最后空轮询未计入 percentile。
ack 单独测量。worker_counts 可用于观察任务分配偏斜。
失败的 trial 不静默忽略；超时、进程异常、数量或 integrity_check 不匹配时整个程序失败。

## 分析方法

保留每 trial 吞吐、claim P50/P95/P99、ack P95 及 worker_counts。
REPORT 汇总吞吐均值和样本标准差；“P95 均值”是各 trial 的 P95 平均，
并非合并所有 trial 请求后重新计算的 P95。
只有三个重复，不提供可靠的总体置信区间或显著性结论。
正式研究应增至至少十次重复、多个 workload 和机器，报告效应量及置信区间。

## 故障注入

`python -m experiments.faults`：

1. 子进程领取任务。
2. 在独立业务 SQLite 数据库提交 receipt 副作用。
3. 使用 pipe 通知父进程已到达故障边界，再 `os._exit(23)`，不调用队列 ack。
4. 父进程验证子进程退出码，以可控时钟越过持久化 deadline，立即重领任务。
5. 重做副作用并确认任务，对比有无唯一 job_id 约束。

此实验是真实进程死亡；恢复时间是受控推进，**没有测量真实等待 30 秒的恢复延迟**。
预期普通副作用=2，幂等副作用=1，两组 attempts=2、最终 done。
业务去重的“1”只适用于同事务的 receipt，不推广到邮件发送或跨系统网络操作。

unittest 还在子进程中打开未提交 ack 事务后直接退出，验证 SQLite 回滚与审计一致性。

## 有限状态验证

模型枚举一任务、两次 claim、抽象过期位、历史 token 的全部可达状态。
允许显式失败、过期、恢复和任意历史 token 的 ack。
正确抽象拒绝过期/旧 token；两个破坏版分别只检查 running 状态，以及检查 deadline
但忽略 generation，模型输出最短反例。
模型不包含 SQL、操作系统、真实时间或多个 job，因此是**设计层验证**而非代码级形式化证明。
代码层还由确定性时钟测试、400 步固定种子历史测试、实际多进程测试验证。

## 已知混杂因素

- 机器仅一台，磁盘型号和同步行为没有独立测量。
- OS page cache、后台任务、杀毒扫描、CPU 频率未控制。
- 测试任务规模小；严禁把峰值解释为长期容量。
- NORMAL 与 FULL 可能改变耐久性，不能当作完全相同服务等级的性能比赛。
- WAL 在当前本机 runtime 被拒绝；没有虚构 WAL 结果。
- 测试没有验证网络分区、多机时钟、硬件掉电、bit rot 或有恶意的 worker。
